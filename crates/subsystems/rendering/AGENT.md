# crates/subsystems/rendering

層: 1 Subsystems

GPUI のオフスクリーン非表示ウィンドウにおける描画、GPU フレームバッファの読み戻し、および VR ランタイムオーバーレイへのピクセル転送を担当する。

VR ランタイムごとの不透明度制御やアタッチ追従能力の差異を吸収し、描画リソースのライフサイクル（確保・パーキング・解放）を管理する。

## 描画パイプラインにおける位置づけ

本クレートは `overlay` の下位、`vr` の上位に位置し、カーネルを通じて `kernel::rendering` として機能を提供する。UI 層から直接本クレートを参照することはない。

- **リソースの保持 (`Surface`)**: 各パネルに対応する `Surface` インスタンスが、ランタイム側のオーバーレイリソースと送信済みテクスチャの状態を保持する。パネルの姿勢計算やアニメーション進行は `overlay` が決定し、ランタイムへの転送時の能力差は `Surface` が吸収する。
- **表示サーバーの画像 (`store_external`)**: Linux の画面の配信では、表示サーバーの画像（`vr::ExternalImage`）をランタイムの GPU に直接取り込ませる。書き込み元のバッファを占有しないよう、送信した後は画像を保持しない。そのため、不透明度や明るさをランタイムで合成できない場合も、この画像の画素は加工しない（OpenVR と、color_scale_bias 拡張を持つ OpenXR は合成できる）。
- **一時退避 (`park` / `restore`)**: 非アクティブなパネル（非表示のナビゲーションバーなど）は、`park()` によってランタイム側のリソースのみを解放し、メモリ上の画像データと描画順情報を維持する。再注視時は `restore()` により同一キーで再生成される。
- **フォーマット変換**: GPUI の内部描画形式（BGRA）と VR ランタイムや他クレートが要求する形式（RGBA）との相互変換（`render_image` など）を集約する。

## 主な公開 API

```rust
Surface::{
    new,      // パネル描画サーフェスの生成
    store,    // フレーム画像の保持
    store_external, // 表示サーバーの画像を次の present でランタイムの GPU へ取り込ませる（保持はしない）
    present,  // 不透明度・明暗補正を適用したランタイム転送
    place,    // 空間姿勢の適用
    show,     // 可視性の切り替え
    park,     // ランタイムオーバーレイの一時返還
    restore,  // 退避サーフェスの復帰
    release,  // リソースの完全破棄
};

// GPUI ウィンドウ連携
gpui::{
    application,     // パネルを描画する GPUI アプリケーションの生成（OS ごとのプラットフォームを選択）
    capture,         // ウィンドウ描画のキャプチャ実行
    read_back,       // GPUからのピクセル読み戻し
    open_window,     // オフスクリーンウィンドウの生成
    set_render_lod,  // LOD に応じた描画解像度スケール変更
    render_image,    // ピクセルバッファから GPUI 画像への変換
};
```

## OS ごとの描画ホスト

パネルのウィンドウは、どの OS でも表示サーバー上に表示しない描画先であり、描画結果はピクセルとして読み戻される。ウィンドウを生成する仕組みは OS ごとに異なる。

- **Windows**: GPUI 標準のプラットフォームが非表示のウィンドウを生成し、Direct3D で描画する。読み戻しの非同期化と描画スケールの変更は vendor/gpui_windows に追加してある。
- **Linux**: GPUI の Wayland / X11 のウィンドウは `render_to_image` を実装しておらず、非表示にもできない。そのため `gpui::application` は、ヘッドレスの Linux プラットフォームをラップした `OffscreenPlatform`（`src/gpui/linux.rs`）を返す。このプラットフォームはウィンドウの生成のみを差し替え、各ウィンドウを vendor/gpui_wgpu のヘッドレスレンダラ（wgpu のオフスクリーン描画先）で描画する。表示サーバーには接続しないため、SteamVR から表示サーバーなしで起動された場合でも動作する。

Linux の描画ホストは、Windows の描画ホストと同じ振る舞いを次の方法で実現している。

- **描画の互換**: vendor/gpui が拡張したシーン（角丸クリッピング、超楕円の角、回転）は、vendor/gpui_wgpu の WGSL が vendor/gpui_windows の HLSL と同等に描画する。描画先は透明で下塗りし、事前乗算アルファの画素を返す。
- **読み戻しと LOD**: 読み戻しは GPU の完了を待たず、前回の描画結果を返す（1 回遅れ）。`collect_readback` と `with_render_scale` は vendor/gpui_windows の同名の関数に相当し、`collect` と `set_render_lod` から OS に応じて呼び分ける。LOD の描画解像度は、フレームループの照合に合わせて `解像度 >> lod`（切り捨て）とする。
- **テキストシステム**: Zed のワークスペースは gpui_linux を表示サーバーの機能なしで依存に含めるため、ヘッドレスのテキストシステムは字形を描画しない。`OffscreenPlatform` は gpui_wgpu の `CosmicTextSystem` を使用し、書体を指定しない文字（`.SystemUIFont`）には fontconfig が選ぶ sans-serif を割り当てる（Windows の Segoe UI に相当）。
- **URL の起動**: ヘッドレスのプラットフォームは URL を開かないため、`open_url` は xdg-open を呼び出す。
- **パイプラインの共有**: パネルごとにレンダラを生成するため、シェーダーのパイプラインは同じ GPU デバイス上のレンダラ間で共有する（vendor/gpui_wgpu）。共有しない場合、パネルを開くたびに約 18ms（2 フレーム）を要した。

### GPUI 自身のフレーム

GPUI は、プラットフォームがフレームを要求したとき（`on_request_frame` のコールバック）に、再描画が必要なウィンドウの描画と、次のフレームのコールバック（`request_animation_frame`）の実行を行う。部品はアニメーション中に描画のたびに次のフレームのコールバックを登録するため、フレームが一度も要求されなければ、このコールバックは実行されないまま蓄積する。入力を伴わない変更（`cx.notify`）も、フレームループが次に描画するまで反映されない。

一方、読み戻す描画はフレームループが担い、遠いパネルの間引きと隠れたパネルのカリングを行っている。GPUI のフレームを毎フレーム要求すると、GPUI がこれらのパネルも描画してしまい、間引きとカリングが無効になる（`stress` で計測したフレーム落ちは、パネル生成の段階で 4.6% から 10.8% に増加した）。そこで Linux の描画ホストは、GPUI のフレームを次の条件でのみ呼び出す。

- フレームループが直近 2 秒以内に描画したウィンドウ（表示中のウィンドウ）であること。
- フレームループが直近 100ms 以内に描画していないこと。ただし、要求から 1 秒が経過した場合は、蓄積したコールバックを実行するために呼び出す。

## テスト手法

`cargo test -p rendering --all-features` を実行し、ピクセルフォーマット変換、アルファブレンド処理、追従フォールバック、およびリソース解放後の更新抑止ロジックを検証する。

Linux の描画ホストの描画結果は、ui の GPU テスト（`cargo test -p ui --test gpu -- --ignored`）で検証する。シェーダーとレコードのレイアウトは vendor/gpui_wgpu のテストで検証する（vendor はワークスペース外のため、`vendor/gpui_wgpu/Cargo.toml` の先頭の手順で実行する）。
