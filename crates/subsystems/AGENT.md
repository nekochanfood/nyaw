# crates/subsystems

層: 1 Subsystems

OS、VR ランタイム、コントローラ入力機器、および描画環境の差異を吸収する中核クレート。下位サブシステムを統括して入力履歴を保持し、上位層に対して生入力を含まない正規化された共通フレーム（`Frame`）を供給する。

上位の設定管理、パネル管理、UI ロジックには一切依存しない。

## アーキテクチャ境界と責務分離

OS やハードウェアの差異を本クレートおよび配下のサブシステムクレート内に閉じ込めることで、上位層における環境別の条件分岐を排除する。

```text
アプリケーション
├ UI（GPUI による描画と入力変換）
├ オーバーレイ（3次元空間パネル管理・姿勢計算）
└ カーネル（設定・フレーム進行・全体統括）
    └ Subsystems（crates/subsystems）
        ├ os/            OS 差異（パス、高精度タイマー、OS 入力）
        ├ vr/            VR ランタイム（OpenVR / OpenXR / novr）
        ├ input/         コントローラ機種プロファイルと共通アクション変換
        ├ rendering/     GPUI オフスクリーン描画・ピクセル転送
        ├ audio/         音声出力・空間音響処理
        ├ desktop/       画面・ウィンドウキャプチャと OS 入力注入
        ├ media/         再生中メディアの取得・制御
        ├ notifications/ OS 通知の監視と起動連携
        └ keyboard/      仮想キーボード配列データ
```

### 実装原則

- **共通フレームの供給**: `Subsystems::poll()` は、ランタイムの生入力取得、機種別プロファイル変換、およびヒステリシス計算を内部で完結させる。生成される `subsystems::Frame` は正規化された `ControllerState` 配列、デバイス姿勢、トラッカー情報、および終了要求のみを含み、生入力や機種プロファイル名は上位へ露出させない。
- **入力履歴の管理**: コントローラの接続切断や機種変更が発生した際は、内部で保持している入力履歴を即座に破棄する。
- **上位層の非関知**: オーバーレイ層は正規化された共通アクションのみを受け取り、光線交差判定やドラッグ操作を処理する。ハードウェア固有の閾値やプロファイル差分を意識することはない。
- **OS バックエンドの分離**: 現在の主バックエンドは Windows であるが、サブシステム境界は特定 OS に依存しない設計を維持する。将来的な他 OS への対応も、上位層を変更することなくバックエンドの追加によって実現する。

## 主な公開 API

```rust
Subsystems::{
    with_backend,  // 指定バックエンドでの初期化
    poll,          // フレーム更新と共通 Frame の取得
};
Frame;             // HMD姿勢、コントローラ状態、終了要求を含む共通フレーム
ControllerState;   // 正規化されたコントローラ状態
os;                // OS サブシステムの再エクスポート
rendering;         // 描画サブシステムの再エクスポート
```

## 各サブシステムとの協調方針

- **ログ出力**: ログの保存先パスは `subsystems::os` が提供するが、ファイル出力、世代管理、およびローテーション方針は `logger` が所有する。
- **リソース解放**: パネル終了時のフェード完了を待ってリソースを解放する判断は `overlay` が担い、`subsystems::rendering` は指示された破棄要求のみを実行する。
- **ウィンドウの性質**: 非表示や透過といったウィンドウの運用方針は `ui` が決定し、オフスクリーン描画サイズの補正や LOD スケーリングの実装手段は `rendering` が吸収する。
