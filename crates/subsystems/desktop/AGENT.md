# crates/subsystems/desktop

層: 1 Subsystems

ディスプレイ画面および個別アプリケーションウィンドウの列挙、キャプチャ画像の取得、および OS に対する直接的なタッチ入力の注入を担当する。また、インストール済みアプリの一覧、アプリ ID からの名前・実行ファイル名・アイコンの解決、およびアプリの起動を担当する。

Windows 環境では Windows Graphics Capture (WGC) および Synthetic Pointer API を使用する。

## ウィンドウとアプリケーション情報の突合

ウィンドウの所属判定や後継ウィンドウの追跡など、OS 固有の知識（実行ファイル名や拡張子 `.exe` の扱い）を本サブシステムに集約する。

- `app_key(exe)`: 実行ファイル名を正規化して小文字かつ拡張子なしの検索キーを生成する。
- `InstalledApp::owns(&Source)`: 指定されたウィンドウが該当アプリケーションに属しているかを判定する。
- `Source::replacement` / `Source::successor`: キャプチャ対象のウィンドウが閉じられた際、タイトルやプロセス情報から後継ウィンドウを特定する。

## インストール済みアプリの解決と起動

アプリ ID（Windows は AppUserModelId）からアプリの情報を引く処理と起動は、本サブシステムだけが実装する。`media`（再生中のアプリの名前と実行ファイル名）と `notifications`（通知のアイコンと、通知を押したときの起動）も本サブシステムの関数を呼ぶ。他の OS に対応する場合は、ここだけを実装すればよい。

- `InstalledApps::refresh`: スタートメニューのアプリをすべて列挙する（アイコンを読み込むため数秒かかる）。
- `installed_app(id)` / `app_icon(id)`: 1 つのアプリの情報、またはアイコンだけを引く。
- `launch(id)`: アプリを起動する。シェルの API は STA を前提とするものがあるため、Windows では STA の専用スレッドで `ShellExecuteExW` を呼ぶ。呼び出し元のスレッド（通知のワーカーは MTA）の COM の初期化状態には依存しない。失敗は呼び出し側に返し、OS のエラーダイアログは出さない（VR から見えないため）。

## 画面・ウィンドウのキャプチャと配信

- **非同期ワーカーによる画像取得**: キャプチャ処理はバックグラウンドスレッドで実行され、メインスレッドは `poll()` を介して最新のフレーム画像のみを非同期に受け取る。OS 側の開始・停止・画像読み出しによってメインスレッドがブロックされることはない。
- **カーソル画像の分離取得**: キャプチャ映像内に OS カーソルを直接焼き込まず（WGC の `IsCursorCaptureEnabled` を無効化）、別スレッドが `GetCursorInfo` からカーソルのビットマップとホットスポット座標を独立して取得する。取得したカーソル画像は `Overlay::set_os_cursor` を通じて VR 空間内のポインタ表示へ反映される。
- **アスペクト比の追従**: パネルは元のキャプチャ解像度のアスペクト比を維持して表示される。ダッシュボードにドッキングしている間は縦方向の寸法が固定され、横幅が比率に応じて追従する。
- **メニューの分離取得**: 右クリックやタイトルバーのメニューは取得元とは別のウィンドウなので、WGC のウィンドウ取り込みの映像には入らない。そこでワーカーが、取得元より手前にある同じプロセスのポップアップ（タイトルの無い `WS_POPUP` のウィンドウ）のうち、取得元に重なるものと、それに重なるもの（はみ出したサブメニュー）を集め、**メニューのウィンドウごとに WGC で取り込んで** `Stream::popups` で渡す（`Popup`）。位置と大きさは取得元の幅・高さを 1 とした値で、取得元の外へはみ出すことがある。画像は事前乗算アルファで、メニューのウィンドウだけが映る。角の丸めの外側や、アプリが影のために持つ余白は透明のまま届くので、切り抜きは要らない。取り込みはメニューが出ている間だけ保ち（D3D の装置は取得元と共用する）、黄色い枠は出さない（`SetIsBorderRequired`）。画面を切り出す方式（`BitBlt`）は透明な所に後ろのウィンドウが写るので使わない。`IncludeSecondaryWindows` は取得元ごと映り、はみ出したメニューが取得元の範囲で切れるので使わない。調べ直す間隔は映像の FPS に合わせるが、FPS を下げていても 33ms ごとには行う。上位層はこれを配信パネルに重ねる子パネルとして描く（[`../../kernel/AGENT.md`](../../kernel/AGENT.md)）。

## OS 入力注入とウィンドウフォーカス制御

- **タッチ接点としての入力注入**: 配信パネルに対するポインタ操作は GPUI のマウス変換を経由せず、左右の手をタッチ接点（ID 0 / 1）として OS 側へ直接注入する。手の追跡喪失やパネルの把持開始時にはタッチが自動キャンセルされる。
- **メニューへの入力**: 接点の座標（`Touch`）は取得元の幅・高さを 1 とした値で、はみ出したメニューを指せるよう、取得元 1 つ分外側まで受け付ける。押した所が取得元ではなくても、渡したメニューのウィンドウであれば入力を送る。
- **対象ウィンドウの前面化 (`FocusSource`)**: ウィンドウの配信開始時やダッシュボードでの切り替え時、対象ウィンドウを最小化から復帰させ、`SetForegroundWindow` を通じて OS の入力フォーカスを取得する。この処理も非同期ワーカー側で実行される。
- **未起動アプリの起動ハンドリング**: ランチャーから未起動のアプリを選択した場合、起動プロセスを要求すると同時に起動待機画面（`launch_spec`）を展開する。0.5 秒間隔で新規ウィンドウの出現を監視し、検出された段階で即座に配信へ移行する（20 秒間検出されない場合はタイムアウト表示）。

## 主な公開 API

```rust
Sources;                 // キャプチャ元（ディスプレイ・ウィンドウ）の一覧管理
Stream;                  // 個別キャプチャセッションの制御
Source;                  // キャプチャ元情報（名前、アプリアイコン、製品名等）
Cursor;                  // OS カーソル画像とホットスポット情報
Popup;                   // 取得元の手前に出ているメニュー（位置・大きさ・画像）
capabilities();          // ホバーや最小化対応などのバックエンド能力問い合わせ
InstalledApps;           // インストール済みアプリの一覧の取得（別スレッド）
installed_app(id);       // アプリ ID からのアプリ情報の取得
app_icon(id);            // アプリ ID からのアイコンの取得
launch(id);              // アプリの起動
```

## テスト手法

- **単体・モックテスト**: `desktop/test-support` フィーチャーを有効化し、モックを用いて最新画像の更新、タッチイベントの配送、およびセッション終了処理を検証する。
- **アプリの解決と起動の実機検証**: `cargo run -p desktop --example apps` で一覧を出力し、各アプリを ID から引き直した結果が一覧と一致するかを確認する。`cargo test -p desktop -- --ignored launches_an_app_from_an_mta_thread` は電卓を MTA のスレッドから起動する。
- **実機キャプチャテスト**: `crates/subsystems/desktop/tests/windows_capture.rs` および `testkit/tests/scenarios/desktop_stream.rs`（いずれも `#[ignore]` 指定）を用いて実デスクトップ環境での動作を検証する。
