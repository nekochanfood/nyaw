# デザインガイドライン

VR 空間内に配置されたパネルをコントローラのレーザー光線で操作することを前提とした UI 設計規範。

単一の情報源（Single Source of Truth）である `tokens.json` の定数値を基盤とし、本ガイドラインでは視覚的整合性と操作性を保つための設計規則を定める。

設計における優先順位は次の通りとする。

```
コントラストの確保とカモフラージュの防止 > 操作領域の確保 > 可読性の維持 > モーションの統一
```

## 基本原則

### 操作領域の確保（押しやすさ）

- **最小ヒット寸法の遵守**: レーザーポインタによる操作精度を考慮し、すべての操作要素の当たり判定は最小 **48px** 以上とする。視覚的な描画サイズが小さい要素であっても、判定領域を広げて 48px を確保する。
- **隣接要素の間隔**: 誤操作を防ぐため、隣接する操作対象同士の間隔は `spacing::SM`（8px）以上を確保する。
- **視覚的フィードバック**: 通常、ホバー、押下、フォーカスの各状態は明確な明度差で区別する。VR 環境では対象に触れずに直接トリガーを引く操作も発生するため、ホバーを経由しない押下であっても操作が成立する設計とする。
- **破壊的操作の隔離**: データの削除や初期化などの破壊的操作には `danger`（赤系）を適用し、通常の操作ボタンから物理的に離れた位置へ配置する。

### 視認性と可読性

- **基準フォントサイズ**: 本文の文字サイズは `font_size::MD`（19px）を基本とし、`font_size::SM`（14px）未満の極小フォントは使用しない。
- **VR 環境への配慮**: 解像度制限と視距離による文字潰れを防ぐため、細いフォントウェイト、過度な字間詰め、低コントラストの組み合わせを避ける。
- **動的スケーリングの前提**: 文字サイズおよび太字化の設定（80〜150%）は GPUI のレイアウト基盤で一括適用される。コンポーネント実装時は等倍の寸法をそのまま記述し、文字を内包するコンテナは固定高さを避けて可変（または `font::scaled` で倍率連動）とする。
- **装飾文字の除外 (`.text_exact()`)**: 腕時計パネルの文字盤やキーボードのキートップなど、グラフィックデザインの一部として機能している文字に限り、`.text_exact()` を付与して動的スケーリングから除外する。
- **テキストコントラスト比**: 本文テキストは背景に対して 7:1 以上（`neutral-text`）、補助テキストは 4.5:1 以上（`text-low`）のコントラスト比を維持する。

### モーションの統一

- **イージングの一貫性**: アニメーションには `animation::Motion` で定義された標準イージング（Enter / Exit / Move / Morph / Slide 等）を使用する。退出アニメーションは進入アニメーションの逆再生（同等時間かつ反転イージング）を原則とする。
- **コンポーネント内の記述**: 各コンポーネントは `Transition` または `Animation` の状態を保持するのみとし、独自の手書き補間やイージング計算を記述してはならない。
- **所要時間の選定**: 状態変化は `fast` / `quick`、パネルやダイアログの出入りは `normal`、空間内の大きな移動は `slow` を適用する。不要な再描画負荷を避けるため、装飾目的のみの動作は排する。

## レイヤー構造と配色設計

インターフェースは基本的に**カード（Card）**を単位として構築する。3 つのレイヤーを明度差によって重ね合わせる。

```
背景 (Panel) < カード (Card) < 操作部品 (Control)
```

1. **背景とカードの明度関係**:
   - カードは背景よりも常に明るい。ライトテーマでは背景をわずかに落とした白（明度 95〜97%）とし、カードを完全な白とする。ダークテーマにおいてもカード側の明度を背景より高く設定する。
2. **カードと操作部品の明度関係**:
   - ボタンなどの操作部品は、カード内に内包されることを前提とする。
   - ダークテーマでは手前のレイヤーほど明るくする。操作部品はカードよりやや明るい明度とし、ホバー、押下の順にさらに明るくする。
   - ライトテーマではカードが完全な白のため、操作部品はカードよりやや暗い明度とし、ホバー、押下の順にさらに暗くする。
   - スライダーのトラック（未充填領域、`groove`）はくぼみを表すため、両テーマともカードより暗くする。
3. **背景直下に配置する部品 (`Variant::OnBackground`)**:
   - カードの外（パネル地の上）に直接配置されるボタンは、背景と同化することを防ぐため、背景専用の配色（`control-on-background`）を使用する。
4. **背景パネルの省略基準**:
   - 単一のカードのみで構成されるパネル（`components::card_panel`）では、背景レイヤーを敷かずカード自体をパネル外形とする。不要な余白を排除して情報密度を最適化する。

### コントラストとカモフラージュ防止

隣接する要素同士が同化して見分けがつかなくなる現象（カモフラージュ）を厳格に排除する。

- **明度差の確保**: 通常時だけでなく、ホバー時や押下時においても隣接要素との境界が識別可能でなければならない。
- **多重属性による伝達**: 選択状態や重要情報は、明度や色彩の差だけに依存せず、チェックマーク、アイコン、ラベルなどの形状情報と併用して伝達する。
- **パーソナルカラーの制限**: ユーザー指定のアクセントカラー（`accent-solid`）はボタン等の塗りにのみ適用し、文字色や広い背景面へ拡大適用しない。塗りの上に重なるテキストやアイコンには、明暗を自動判定する `on-accent` を必ず使用する。

## コンポーネント別の設計規約

### ボタンと操作要素

- **角丸の形状**: プッシュボタンの角丸は原則として `radius::FULL`（真円カプセル形）とする。
- **高さと余白の比率**: 高さは固定値とし、内部要素は上下左右中央に配置する。文字サイズ 19px（`font_size::MD`）の場合、高さ約 54px、左右余白約 32px を基準とする（高さ 48px を下回らない）。
- **無効状態の明示 (`disabled_button`)**: 「設定中」などの押下不能な現在状態を示す場合は、塗りを持たない枠線のみのカプセルにチェックマークを添えて表示する。ホバーによる色変化や波紋演出は発生させない。
- **アイコンボタン (`icon_button`)**: 幅と高さが等しい正方形（1:1）とし、説明用ツールチップの指定を必須とする。

### メニューとポップオーバー

- **行の設計**: ドロップダウンやポップオーバー内の行高さは、最小ヒット領域に合わせた 48px（`MENU_ITEM_HEIGHT`）とする。
- **配置方向**: 選択ポップオーバーは対象ボタンの下部に中央揃えで展開することを基本とし、画面下端付近に配置された要素に対しては上方向へ展開する（`dropdown_popover::up`）。

### ツールチップ

- **出現位置と追従**: ツールチップは要素に固定されず、カーソル位置のわずかに外側へ追従して表示される。視界内のコントローラ位置（手元）と反対側の方向へ展開する。
- **表示持続時間**: ポインタが対象要素から離れても 0.125 秒間は表示を維持し、隣接する要素へ移動した際の画面のちらつきを抑制する。
- **補助機能としての位置づけ**: ツールチップは補足説明に限定し、操作に不可欠な主情報をツールチップ内にのみ隠蔽する設計は行わない。

### ダイアログ

- **レイアウト構成**: 上部に見出し（アイコン・タイトル・説明）、下部に操作ボタン群を横一列で配置する。右端に肯定的な主操作（`Variant::Primary`）、左端に否定・キャンセル操作を置く。
- **寸法の基準**: 幅は 560px（`components::DIALOG_WIDTH`）を標準とし、高さはテキストの行数に応じて自動計算する。説明文が長大な場合のみスクロール領域を設ける。

### パネル外形とナビゲーションバー

- **パネルの角丸と影**: パネル外周には `radius::XL` の角丸を適用し、角の外側は透過とする。パネル間の重なりを識別可能にするため、全方向へ均等に拡散する拡散影をテクスチャ内に描画する。
- **ナビゲーションバーの標準装備**: パネル上部（または下部）にはタイトル表示と閉じるボタンを備えたナビゲーションバーを既定で配置する。
- **ナビゲーションバーを省略する条件**:
  - 手首パネル（Wrist）などの常駐型パネル。
  - ダッシュボードの操作バー本体。
  - 応答を必須とする子ダイアログ。
  - ポインタやツールチップなどの視覚オーバーレイ要素。
  - 仮想キーボード。

## 幾何学的調和（同心の角丸）

入れ子構造となるコンテナと内部要素は、角の円弧の中心点を一致させることで視覚的な調和を保つ。

- **角丸の計算式**:
  $$\text{内側の角丸} = \text{外側の角丸} - \text{余白間隔}$$
  外側の角丸が 24px（`XL`）で余白が 12px（`MD`）の場合、内側要素の角丸は 12px（`LG`）に設定する。
- **例外**: `radius::FULL` を持つカプセル型要素（ボタン等）は高さの半分が角丸となるため、この式の適用外とし、配置領域側の余白でバランスを調整する。
