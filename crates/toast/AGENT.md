# crates/toast

層: 5 画面

OS から受信した通知メッセージのトースト表示を提供する。単一のパネルインスタンスを使い回し、ユーザーの状況に応じて「視界端（HUD）→ 手首の時計上 → ダッシュボード上」へと配置を動的に遷移させる。

ナビゲーションバーは付与せず、表示位置はシステムの状態から自動的に決定される。

## 通知の遷移フロー（ウォーターフォール）

受信した各通知は「HUD → 手首 → ダッシュボード → 処理済み」という不可逆の段階を持つ。

既に読まれた通知（通知センターの一覧に表示された、またはクリックされたもの）はいずれの段階であってもトースト表示から除外される。

| 周囲の状況 | トーストの配置場所 | 対象通知と状態遷移 |
|---|---|---|
| 通知センター（クイック設定一覧）が表示中 | 非表示 | 未処理の通知をすべてダッシュボード段階へ進める。 |
| ダッシュボードが表示中 | ダッシュボード上部（`Parent::stack`） | 未処理の全通知を表示し、ダッシュボード段階へ進める。 |
| 手首の時計を注視中（`gazed`、視線離脱後 1.5 秒保持） | 手首の時計の上部（`Parent::slot`、視線側へ 0.3rad 傾斜） | HUD および手首段階の通知を表示し、手首段階へ進める。 |
| 直近の受信から 10 秒以内 | 視界の端（設定された `notification_anchor`） | HUD 段階の通知を表示。 |
| 上記以外、またはロックダウン中 | 非表示 | ― |

### 空間移動とアニメーション

- **瞬間移動とフェード**: トーストが場所を移動する際は、視界を横切ってユーザーの視野を遮ることを防ぐため、現在の場所で完全にフェードアウト（約 0.2 秒）した後に次の出現位置へ瞬間移動し、フェードインして再出現する。
- **視距離と解像度密度の最適化**: どの出現位置であっても見かけの寸法が一定となるよう、配置場所に応じてピクセル密度（px/m）を切り替える。
  - HUD: 600 px/m（1.5m 先に配置、気付きやすさのためやや大きめ）
  - 手首: 3000 px/m（至近距離での高精細表示）
  - ダッシュボード: 1000 px/m（ダッシュボード画面と同一基準）

## 表示形態と操作仕様

- **HUD カプセル**: 視界の端に表示される小型のカプセル型 UI（`toast-hud-<id>`）。アイコンと 1 行の見出しのみを表示する。コントローラレーザーの当たり判定は素通り（`PanelCommand::PassThrough`）し、ゲームプレイを妨げない。
- **手首・ダッシュボードカード**: アイコン、見出し、アプリ名、および 2 行に省略された本文を表示するカード型 UI（`toast-<id>`）。クリックするとダッシュボードが展開され、通知センター内で詳細が表示される。
- **並び順と上限**: 常に最新の通知が最上部に配置される。新規通知が届くと上から落下して下のカードを押し下げ、最大 3 件まで並ぶ。4 件以上の場合は下部に「ほか n 件」（`toast-more`）のバッジを表示する。
- **スワイプによる片付け**: 手首およびダッシュボード上のカードは、水平方向にスワイプ（ドラッグ移動）して幅の 30% を超えた位置で解放すると、横方向へ滑らかに消去され、下のカードが繰り上がる。トースト表示からは消えるが、OS 側の通知センターや nyaw 内の通知一覧には保持される。

## HUD のセーフエリア配置

HUD の表示位置は、HMD の両目で確実に視認可能なセーフエリア（`vr::Fov::safe`、視野の 40%、左右 15 度・上下 12 度以内）の境界に沿って配置される。1.5m 先の空間に配置され、頭部の向きに正対する。UI スケールが拡大された場合でも、セーフエリアの外側へはみ出さないよう座標が補正される。

## 主な公開 API

```rust
spec(wrist, opened);                  // パネル起動仕様の生成
Toast;                                // トースト管理構造体
Place;                                // 出現場所の列挙型
hud_pose(anchor, safe, scale);        // HUD 座標の計算
HUD_DISTANCE;                         // HUD の出現距離（1.5m）
RES_PX;                               // 基準ピクセル解像度
```

## テスト手法

- **単体テスト (`cargo test -p toast`)**: 状態遷移ロジック（`flow::tests`）、フェード完了後の位置移動、最新通知のソート順、スワイプ片付け挙動、および各種 HMD 視野におけるセーフエリア境界の収まりを検査する。
- **E2E シナリオテスト (`cargo test -p testkit --test notifications`)**: 実時間タイマーを用いたフルパイプラインテスト。視線の上下による HUD と手首間の移動、ダッシュボード展開時の引き継ぎ、および通知センターからのアクション実行を検証する。
