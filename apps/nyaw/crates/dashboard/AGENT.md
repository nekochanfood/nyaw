# crates/dashboard

層: 5 画面

ダッシュボード画面を提供する。コントローラのショートカットから呼び出され、画面ミラーリング、メディア再生制御、通知一覧、およびランチャーの操作を集約する。

## 開閉動作と表示制御

ダッシュボードの表示と非表示は、ユーザーのショートカット入力または外部領域への操作によって制御される。

- **ショートカット入力**: 左手の X ボタン（Oculus Touch では X、Valve Index では左手 A、Vive では左手のトラックパッドのクリック、Steam Frame では左手の十字キーの下、novr ではキーボードの X、ハンドトラッキング時は手のひらを顔に向けて親指と小指を 0.5 秒間接触）を、規定時間以内（`kernel::DOUBLE_PRESS`、250ms）に 2 回連続で押すと開閉が切り替わる。
- **入力の配送経路**: カーネルはダッシュボードの存在を直接認識せず、左手 X の押下回数を `PanelStatus::double_press` として記録する。実際に開閉コマンドを発行する責務は `wrist` クレートが担う。
- **空間の暗転演出**: ダッシュボードが開いている間は、背景の視界全体を半透明の暗幕で覆うベール演出が適用される（`PanelSpec::with_veil`）。暗幕の濃さは設定値（`Settings::dashboard_dim`、既定値 0.5）で変更できる。
- **外部クリックによる閉塞**: 表示中にダッシュボードおよび他の全パネルの当たり判定外でトリガーを押すと（`PanelStatus::outside_press`）、ダッシュボードは非表示になる。チュートリアルの案内中は、開閉を許す手順でだけ隠す。
- **状態の保持**: 閉じる処理（`dashboard::hide`）はパネルを破棄せず不可視化するのみであるため、実行中の画面配信は停止しない。次回表示時（`dashboard::show`）は前回の状態のままユーザーの正面に再出現する。

## 空間配置と姿勢計算

ダッシュボードの基盤となる操作バー（`Dashboard`）は、ユーザーが直接掴んで移動できる独立したパネルである。初期状態では画面をドッキングせずバー単体で出現する。

ドッキングされた画面が設定値（`Settings::dashboard_distance` / `dashboard_height`、既定値は正面 1.3m、目の高さの 0.05m 下を基準とする相対高さ）の位置に垂直に正対するよう、バーはその下端に配置される。バーは呼び出されるたびに現在の視界の正面へ再配置され（`dashboard::pose`）、表示中に設定が変更された場合も即座に座標が更新される。

## 操作バーの構成

バー上には、左から右へ向かって以下の操作要素が配置される。

1. **メニュー (`dashboard-menu`)**: バー左端の上に固定されたポップオーバー（`PanelSpec::popover`）を開く。
   - デバッグ (`menu-debug`): 検証用画面（Testing）を表示する。リリースビルドでは項目自体を除外する。
   - 設定 (`menu-settings`): 設定画面（[`crates/settings`](../settings/AGENT.md)）を開く。
   - 終了 (`menu-quit`): 視界中央に終了確認ダイアログ（`ui::quit_dialog`）を表示し、承認時にアプリケーションを終了する。
2. **時刻と通知件数**: 固定幅の時刻表示と、未読通知が存在する場合のベルアイコンおよび未読件数バッジ（`dashboard-quick-settings`、`dashboard-notification-count`）。
3. **再生中インジケーター (`dashboard-now-playing`)**: システム内で音声や動画が再生されている場合のみプレイリストアイコンを表示する。
4. **ミラーリング追加ボタン (`dashboard-mirror`)**: 「+」アイコンのボタン。押下すると画面・ウィンドウの一覧を表示する。
5. **更新通知 (`dashboard-update`)**: 新しいリリースが存在する場合にアクセント色で表示される。押下すると設定画面の更新カテゴリを開く。リリースの確認は起動時および 6 時間間隔で行われる（リリースビルドのみ）。
6. **配信ボタン群 (`dashboard-stream-<PanelId>`)**: 区切り線を挟んで右側に配置される。現在開いている画面（ディスプレイアイコン）やウィンドウ（アプリアイコン）の切り替えボタンが並び、枠を越えると水平スクロールする。

## 画面のドッキングと分離

バー上の各ボタンを押すと、該当する画面（独自のナビゲーションバーを持つパネル）がバーの上部スロットへ吸着（ドッキング、`ui::dock`）する。

- **画面の切り替え**: 既に別の画面がドッキングしている状態でボタンを押すと、先行する画面は破棄されずに非表示化され、選択された画面がバー上へ展開される。同一ボタンの再押下で画面を閉じる。
- **配信切り替え時のキーボード引き継ぎ**: ある配信から別の配信へ表示を切り替える際、展開中の OS 仮想キーボードは閉じずに次の配信対象へフォーカスを引き継ぐ（`ui::keyboard::hand_over_os_keyboard`）。
- **ドラッグによる分離**: ドッキング中の画面自体、またはそのナビゲーションバーを掴んで手前へ引くと、ドッキングが解除されて 3 次元空間内に独立した浮遊パネルとなる。
- **吸着による再ドッキング**: 分離した画面を空いているバー上へ近づけて解放すると、磁石のように位置が補正されて再ドッキングする。吸着判定とガイド枠の表示は `overlay` および `beam` が処理する。
- **ナビゲーションメニューからの操作**: ナビゲーションバーの「…」メニューから `nav-undock` を選択して手前へ分離し、`nav-dock` でバー上へ戻すこともできる。

## 各機能ページ（Page）の仕様

### ミラーリング画面（Screen）

接続ディスプレイおよび個別ウィンドウのキャプチャ元をグリッド状のタイル（`dashboard-source-N`）として一覧表示する。タイルを選択すると一覧パネルが閉じて対象の配信パネルがバー上にドッキングし、バー側に個別配信ボタンが追加される。この際、OS 操作用の仮想キーボードは頭部前方の操作しやすい位置へ独立して出現する。

### メディア再生制御画面（Screen）

再生中メディアのジャケット画像をぼかした背景レイヤーの上に、明暗に応じたテーマ背景を薄く重ねて表示する。

- **アプリ連携 (`now-playing-app`)**: 左上に配置されたアプリアイコンを押すと、該当アプリケーションのウィンドウを配信パネルとしてドッキングする。
- **シークと情報表示**: 中央上部からアートワーク、楽曲タイトル、アーティスト名、および無彩色のシークバー（`now-playing-seek`）を配置する。シークバーはドラッグハンドルを持たず、クリック位置へ直接シークする。
- **再生操作**: 前へ、再生/一時停止、次への制御ボタン、および再生経過時間と総曲長を表示する。

### クイック設定・通知センター（Screen）

上部に固定幅の時刻（`quick-time`）、ベースライン補正を行った日付（`quick-date`）、および設定ボタン（`quick-settings-open`）を配置する。

- **一括消去 (`notifications-clear`)**: 「すべて消去」を押すと、各通知カードが 60ms 刻みで水平方向にアニメーションしながら順次消去され、OS の通知センターからも削除される（全体の消去時間は最大 0.6 秒）。
- **通知一覧 (`notifications-list`)**: 新着順にスクロール可能なリストで表示する。受信時刻は 1 分以内を「今」、以降経過に応じて「n分前」「n時間前」「n日前」、1 週間以上経過したものは日付表記とする。
- **通知カード (`notification-<id>`)**: ポインタのホバーにより本文領域が滑らかに伸長し、アクションボタンやアプリ起動ボタンを表示する。カードをクリックすると対象を開き、左右へスワイプすると個別消去される。
- **トースト連携**: トースト通知をクリックした際はダッシュボードが自動展開されてクイック設定がドッキングし、該当通知の詳細が表示される。クイック設定に表示された通知は既読として処理される。

### ランチャー画面

起動中のアプリケーションおよびシステムにインストールされている全アプリケーションを、GPUI の仮想化リストを用いて表示する。チュートリアルの案内中は、起動中のアプリの先頭に練習用ウィンドウのタイル（`dashboard-practice`）を置く。アプリケーション一覧の走査は負荷が高いため、ダッシュボード初期化時にバックグラウンドスレッドで先行取得し、アイコン画像への変換も非同期で実行する。

## チュートリアル

セットアップの完了（またはデバッグ画面の `tutorial`）で頼まれると（`ui::tour::start`）、ダッシュボードが表示されたときに基本の操作を案内する（`tutorial.rs`）。焦点の外を暗くして入力を止める仕組みは UI 層の `ui::tour` にあり（[`../ui/AGENT.md`](../ui/AGENT.md) の「案内（ツアー）」）、ここは手順、案内のパネル（`Coach`）、練習用のウィンドウ（`Practice`）を持つ。

- **案内のパネルの大きさ**: 正方形（640 × 640px、0.512 × 0.512m。1px = 0.8mm）で、どの手順でも変えない。距離による LOD は受けない（`PanelSpec::full_detail`。いつも最高の精細さで描く）。
- **案内のパネルの置き場所**: 開始画面はダッシュボードにはめて開く（`ui::dock`）。始めると外れてバーの子（はめない）になり、手順ごとに説明する所の近くへ滑らかに動く（`PanelCommand::Offset`。置き場所は `Spot`、頭から見た姿勢は `coach_pose`）。どの置き場所も頭からの距離をはめた所と同じにして頭のほうへ向け、見かけの大きさを変えない。バーのボタンを説明する手順では、画面がはまっていなければバーの上（はめた所と同じ位置）、はまっていれば画面の右。画面の手順は画面の右（頭から見て画面の右端から 2° 空ける）、画面の下のバーを説明する手順は画面の右の下寄りで、その手順でユーザーが画面を閉じたら空いたはまる所（ダッシュボードの中央）にはめる（入った時点で画面が無くてもはめない。入るときにクイック設定を開いてはめるので、はめた案内のパネルがそれに押し出されて閉じてしまう）。バーの子なので、ダッシュボードと一緒に動き、一緒に隠れる。開始画面へ戻ると、はめ直す。
- **開閉の手順で閉じたとき**: ダッシュボードが隠れたら、案内のパネルを外して出し直し、セットアップウィザードと同じく頭にゆるく付いてこさせ（`LazyFollow`。今の置き場所と同じ距離・高さ）、ボタンの無い表示で開き方だけを出す（`tutorial-hint`。左手のコントローラを寄って映す）。案内のパネルはバーより後に開くので、隠すのと出し直すのが同じフレームに入り、消えかけて見えることはない。ダッシュボードが出たら、付いてこさせるのをやめて元の置き場所へ滑らかに戻す（付いてこさせ始めるときも `Overlay::set_lazy_follow` が滑らかに動かす）。
- **案内のパネルの中身**: ページの中身（アイコン・見出し・説明・コントローラの画像）は、ウィザードと同じく `components::navigation` で横に滑って入れ替わる（進むと積み、戻ると下ろす）。下の帯と進み具合はページの外に置き、滑らせない。
  - コントローラの画像がある手順は、アイコンと見出しを横に並べ、説明をその下に左端からそろえる。コントローラの枠は下の帯の上に高さを固定し、説明の長さで位置を動かさない。
  - 画像が無く下が空く手順（バー・メニュー）は、ウィザードと同じくアイコン・見出し・説明を縦に並べて上下の中央に置く。完了はウィザードの完了画面と同じく中央にそろえる。
  - 右上の進み具合（`tutorial-progress`）は今の番号を大きく、全体の数を小さく下端にそろえる。番号は 2 桁分の幅の箱の中で右寄せにする（桁が変わっても崩れない）。手順を移ると、前の番号が外へ、今の番号が反対側から滑り込む（進むと下から上へ、戻ると上から下へ）。
  - 下の帯は左に終了（開いたドアのアイコン、`tutorial-quit`）と「戻る」（`tutorial-back`）、右に「次へ」（`tutorial-next`）。終了は確かめるダイアログ（`tutorial-quit-dialog`。案内のパネルの子で、焦点の外でも触れる）で「終了」（`tutorial-quit-confirm`）を選ぶと終える。開始画面は「スキップ」（`tutorial-skip`）と「始める」、完了は「戻る」と「完了」（`tutorial-finish`）。
  - ルートの `debug_selector` は `tutorial-step-<手順>`。
- **コントローラの見せ方**: ショートカットは左手の機種を寄って映して波紋で示し、枠の四辺を地へ溶かす（`guide::zoom` の `edges`）。ほかの操作は利き手の機種に説明を付ける（`guide::controller`。札は左右に振り分け、札と画像をまとめて中央に置く）。映した画面の操作では、右クリック・中クリックで親指を触れておくボタンも示す（それを報告する機種だけ）。
- **進むのは「次へ」**: 案内した操作をしても手順は進めない。例外は、操作の結果がそのまま次の手順の前提になる手順（画面を外す・ランチャーを開く・練習用のウィンドウを選ぶ・しまう。`leads_on`）で、操作をしたら次へ進む。画面を外す手順と戻す手順は一続きで、外したら戻す手順へ進み、戻せたら「よくできました」を出す。操作を案内する手順（開始画面・バー・メニュー・完了を除く）では、「次へ」の左に「やってみましょう」（`tutorial-try`）を出し、済んでいない状態から済んだ状態に変わると「よくできました」（`tutorial-done`）に替えて、その手順の間は出したままにする。「次へ」はそれまで色を付けず（`wizard_next_muted`）、済んだら色を付ける。操作しなくても「次へ」で進める。
- **手順に入るときの状態**: 進んでも戻っても、手順ごとに決めた状態にそろえてから始める（`prepare`）。戻れば、その手順の操作をやり直せる（後の手順で開いた画面や練習用のウィンドウは閉じる）。
  - 開始画面〜クイック設定、ランチャー: ダッシュボードのボタンで開いた画面も練習用のウィンドウも閉じる。
  - 画面を動かす: クイック設定をはめた状態（開いていなければ開き、外していれば、はめ直す）。画面を戻す・画面のバー: クイック設定が開いている（外したままでもよい）。
  - 練習用のウィンドウを選ぶ: ランチャーをはめ、練習用のウィンドウは閉じる。
  - 操作・しまう: 練習用のウィンドウを出す。呼び戻す・完了: 練習用のウィンドウをしまう。
- **戻る**: 前の手順へ戻る（入るときの状態にそろえる）。入った時点で済んでいる操作には「よくできました」を出さない（変わったときだけ出す）。
- **始め方**: 頼まれたときに案内を始め、はめていた画面を外し（配信はしまい、ほかの画面は閉じる）、開いているメニューを閉じる。隠れているかロックダウン中なら、出てから始める。

| 手順 | 焦点 | 「よくできました」を出す条件（※は次へ進む） |
|---|---|---|
| 開始画面 | 案内のパネルだけ | ― |
| バー | バー全体を囲む | ― |
| 開閉 | バー（ショートカットの二回押しと外の押下で開閉できる） | 一度隠れてから出た |
| メニュー | `dashboard-menu` を囲む（押せない） | ― |
| クイック設定 | `dashboard-quick-settings` だけ押せる | クイック設定をはめた |
| 画面を動かす・戻す | はめた画面とバー（つかめる） | ※外した（動かす）・はめ直した（戻す） |
| 画面のバー | その画面のバーの `nav-close` だけ押せる（バーは指していなくても出したまま） | 画面を閉じた |
| ランチャー | `dashboard-launcher` だけ押せる | ※ランチャーをはめた |
| 練習用のウィンドウを選ぶ | ランチャーの `dashboard-practice` だけ押せる | ※練習用のウィンドウをはめた |
| 操作 | 練習用のウィンドウ（入力はすべて通す） | 試せるクリックの的をすべて押し、リストをスクロールした |
| しまう | そのウィンドウのバーの `nav-minimize-source` だけ押せる | ※しまった |
| 呼び戻す | バーの練習用のウィンドウのボタン | はめて出した |
| 完了 | 案内のパネルだけ | ― |

- **練習用のウィンドウ**: 映したウィンドウの代わりにマウスの操作を試す画面。左・右・中クリックの的（`practice-left`・`practice-right`・`practice-middle`。それぞれのボタンでだけ押せ、押すと印が付く）と、スティックでスクロールするリスト（`practice-list`）。右・中クリックを報告しない機種では、その的に「このコントローラでは使えません」と出し、試す数に入れない。配信と同じくバーにボタンを足し、ナビゲーションバー（OS キーボード・しまう・閉じる）を持つ。案内を終えると（スキップ・終了・完了）、案内のパネルと一緒に閉じる。
- **テスト**: 単体は `cargo test -p dashboard -- tutorial`（手順の順序、置き場所、はめた姿勢がオーバーレイ層の置く所と一致すること、どの置き場所も頭からの距離が同じこと、画面の右に置いても画面に重ならないこと、練習用のウィンドウの的がそれぞれのボタンでだけ押せること）。novr の通し操作は `cargo test -p testkit --test scenarios -- tutorial::`（焦点の外が暗く押せないこと、案内した操作で「よくできました」が出て手順は進まないこと（ランチャーを開く・選ぶ・しまうは次へ進むこと）、開閉の手順で閉じると案内のパネルが外れて付いてきて開き方だけを出し、開くと戻ること、画面のバーの手順で画面を閉じると案内のパネルをはめること、完了で練習用のウィンドウをしまうこと、戻ると後の手順で開いたものが閉じてやり直せること、最後まで進んで最初まで戻り、また最後まで進めること（どの手順も入るときの状態で始まる）、「次へ」だけで最後まで進めること、スキップと、確かめてから途中で終えること、はめて開いてから浮かんで動くこと、戻ること）。実 GPU での見た目は `cargo test -p ui --test gpu -- --ignored tutorial`（`target/tmp/tutorial-*.bmp`）。

## 主な公開 API

```rust
dashboard::{spec, pose, hide, show};
dashboard::{coach_pose, CoachSpot, COACH_M, COACH_PX}; // 案内のパネルの置き場所と大きさ（通し操作と GPU の通し確認が使う）
Dashboard;
Menu;
Screen;
Page;
Summon;
OPEN_SOUND;
CLOSE_SOUND;
```

日付の書式化は `i18n::date`、ウィンドウとアプリケーション情報の突合は `kernel::desktop` に委譲する。

## ファイル構成と実装規則

本クレートは画面およびコンポーネント単位で 1 ファイルを割り当てる構成をとる。

`lib.rs` には公開 API（`spec` / `pose` / `hide` / `show` / `Page`）、状態構造体（`Dashboard` / `Screen`）、および共通定数のみを定義し、具体的な振る舞いは各ファイルの `impl` ブロック内に記述する。テストコードは各ファイルの子モジュール（例: `bar/tests.rs`）に配置し、共通テストヘルパーは `test_util.rs` に集約する。

| ファイル | 責務と実装内容 |
|---|---|
| `bar.rs` | 操作バーの描画、各種ボタンの配置、画面のドッキング制御（`impl Dashboard`）。 |
| `menu.rs` | メニューポップオーバー（`Menu`）の表示と終了確認処理。 |
| `screen.rs` | `Screen` の生成、キャプチャ元一覧の監視、ページ種別の振り分け。 |

| `quick_settings.rs` | クイック設定画面の実装。時計表示、通知一覧、通知カードのスワイプ消去。 |
| `mirror.rs` | 配信パネル（`Mirror`）の表示と、起動待機画面のハンドリング。 |
| `parts.rs` | 見出し、グリッド、タイル、時計など、画面間で共有される UI 部品。 |
| `tutorial.rs` | チュートリアルの手順と進め方（`impl Dashboard`）、案内のパネル（`Coach`）、練習用のウィンドウ（`Practice`）。 |
