# 日本語ローカライズガイドライン (Japanese Localization Guidelines)

本ドキュメントは、nyaw における日本語ローカライズ（UI テキスト、チュートリアル、メッセージ等）の文章規範および用語統一基準を定めます。

---

## 1. 基本理念

### 1.1 利用者の体験を行為者として描く
システム内部のアーキテクチャや都合ではなく、「利用者が何を認識し、何を行い、どう操作するか」を利用者本人の視点から描写します。

### 1.2 自信を持った意志表現（will の文体）
過剰な可能表現（「〜できます」「〜開けます」など）の乱用を避け、確固たる確定的な動作（「〜します」「〜開きます」）で言い切ります。
- **悪い例**: `ボタンを押すと、画面を開けます`
- **良い例**: `ボタンを押して、画面を開きます`

### 1.3 システム目線の自己言及を排除する
開発者やシステム側が自己紹介や言い訳をするような語り（「〜を用意しました」「〜を紹介します」「本物のアプリの代わりに」など）を排除します。UI は機能そのものを自然に提示すべきであり、裏方の存在を語る必要はありません。
- **悪い例**: `チュートリアル用に練習用ウィンドウを用意しました。「練習用ウィンドウ」を選ぶとダッシュボードに映ります。`
- **良い例**: `チュートリアル中は、操作を試すための「練習用ウィンドウ」を使用します。一覧から「練習用ウィンドウ」を選んで、ダッシュボード上に表示します。`

---

## 2. 文体・語り・表現規則

### 2.1 能動的な連用形「〜〜〜して」の原則
操作手順やガイド文では、**「〜〜〜すると」ではなく「〜〜〜して」** を基本形とします。

#### 「〜〜〜して」が好ましい理由
- **能動的なタスクフロー（will）の形成**:
  「〜〜〜すると」は「条件と受動的帰結（システムが勝手に反応する）」のニュアンスが強くなり、利用者が受け身になります。一方「〜〜〜して」は利用者が主体となって操作ステップを遂行する能動的なフローを作り出します。
- **認知的負荷の低減とテンポの良さ**:
  連続した操作（例: 「［−］を押して、ダッシュボードに収納します」）を歯切れよく伝えることができます。

| パターン | 避ける表現（受動・条件） | 推奨表現（能動・連用形） |
| :--- | :--- | :--- |
| ウィンドウを開く | ボタンを押すと、画面が開きます | ボタンを押して、すぐ上に画面を開きます |
| メニューを開く | 左端のボタンを押すとメニューが開きます | 左端のボタンを押してメニューを開きます |
| リストのスクロール | スティックを倒すとスクロールできます | スティックを倒してリストをスクロールします |
| ウィンドウの収納 | ［−］を押すと最小化されます | 操作バーの［−］を押して、画面をダッシュボードに収納します |

> **例外（「〜〜〜すると」が適切な場面）**
> 意図しない破壊的操作や警告（不可逆な変更、副作用）を伝える場合に限り、因果関係を明確にするため「〜〜〜すると」を使用します。
> - 例: `保存せずに閉じると、変更内容は破棄されます`

### 2.2 内部実装用語の解消
API・OS パイプライン・内部データ構造の用語をそのまま UI に露出させず、ユーザーにとって直感的で分かりやすい言葉に置き換えます。

| 内部・技術用語 | 避ける理由 | 推奨表現 |
| :--- | :--- | :--- |
| **配信 / キャプチャ** | 動画生配信（YouTube/Twitch 等）と誤認されやすい | **ミラーリング / 画面ミラーリング** |
| **キャプチャ元** | グラフィックパイプラインの内部用語 | **対象ウィンドウ / 対象の画面** |
| **スケルタル入力** | 内部の関節トラッキング API 名 | **ハンドトラッキング** |
| **把持（はじ）** | ロボティクス・学術用語で日常語ではない | **持つ / 握る / コントローラ使用中** |
| **config.toml** | 設定ファイルの実体名をユーザーに意識させるべきではない | **設定 / 設定ファイル** |
| **面に重ねる子 / 奥のパネル** | UI シーングラフ（親子関係・Z深度）の直訳 | **前面レイヤー / 背面パネル** |

### 2.3 上から目線の評価表現の排除
チュートリアルや達成時のフィードバックで、利用者を採点するような上から目線の表現（「よくできました」など）は避け、利用者の達成感に寄り添う表現にします。操作の成功を一緒に喜ぶ「ナイス！」は使用します。
- **推奨**: `ナイス！`、`クリア！`、`完了しました`、`準備完了`

## 3. タイポグラフィと表記規則

### 3.1 和欧文間の半角スペース
日本語文章内に含まれる英文字（ASCII アルファベット、ブランド名、略語、キー名等）の**前後には半角スペースを挿入**します。
- **良い例**:
  - `SteamVR と連動して起動`
  - `PC のアプリやデスクトップ画面`
  - `VR 空間での操作を始めましょう`
  - `次回表示時の上限フレームレート: {rate} FPS`
- **例外**: 句読点（、。）や括弧類（「」、（）、［］）と英文字が隣接する場合はスペースを挿入しません。
  - 例: `「SteamVR」の起動`、`（VR 空間）`

### 3.2 数字の前後の半角スペースは不要（和数間スペースなし）
アラビア数字および数字を表すプレースホルダー（`{n}`、`{count}` など）の前後に**半角スペースは入れません**。
- **良い例**: `2回押して`、`3件連続`、`3本の指`、`最大6行`、`{count}回`、`{n}日前`
- **悪い例**: `2 回押して`、`3 件連続`、`3 本の指`、`最大 6 行`、`{count} 回`、`{n} 日前`

### 3.3 句点（。）の適用ルール
画面の性質と文の長さに応じて、句点（。）の有無を統一します。

- **句点を付ける（。）**:
  - 複数の文からなる説明文・チュートリアルの解説文。
  - ダイアログの詳細説明など、完全な複文で構成される文章。
- **句点を付けない（丸で止めない）**:
  - ボタン名、ラベル、タブ名、見出し。
  - アラート文、エラーメッセージ、トースト通知、ステータス表示などの単文・短文。
  - **良い例**:
    - `対象のウィンドウが閉じられたか、非表示になったか、最小化されました`
    - `お使いの環境では画面ミラーリングを利用できません`
    - `通知が届きました`
    - `すべての設定が完了しました`
  - **悪い例**:
    - `通知が届きました。`
    - `お使いの環境では画面ミラーリングを利用できません。`

## 4. 用語集 (Glossary)

| 原文 (en) | 推奨日本語 (ja) | 避ける表記 | 備考 |
| :--- | :--- | :--- | :--- |
| **Mirroring / Stream** | ミラーリング / 画面ミラーリング | 配信、ストリーミング | PC 画面を VR 内に映し出す機能 |
| **Dashboard** | ダッシュボード | バー、ドック | 手前の主操作パネル |
| **Hand Tracking** | ハンドトラッキング | スケルタル入力、手の入力 | 手の動きを追従する入力方式 |
| **Controller** | コントローラ | コントローラー | プロジェクトの長音省略表記に合わせる |
| **Grab** | つかむ / グラブ | 把持する | 画面を移動させるときの動作 |
| **Pin / Detach** | 固定 / 外す | ロック、アンピン | ダッシュボードから切り離す操作 |
| **Dock / Undock** | 戻す / 外す | 格納、ドック | ダッシュボードとの脱着 |
| **Minimise** | 最小化 / 収納 | しまう | 操作バーの［−］を押したときの動作 |
| **Laser** | レーザー | ビーム、ポインタ光 | コントローラから伸びるポインタ線 |
| **Pointer** | ポインタ | カーソル | 操作点全般 |
| **Quick Settings** | クイック設定 | 簡単設定 | 時計ボタンから開く設定画面 |
| **Launcher** | ランチャー | 起動画面 | アプリやデスクトップを選択する一覧 |
| **Settings** | 設定 | オプション、環境設定 | アプリ全体の設定画面 |
| **Practice Window** | 練習用ウィンドウ | テストウィンドウ | チュートリアル用のダミー画面 |
| **Done / Nice work** | 準備完了 / クリア！ / ナイス！ | よくできました | 上から目線にならず達成感を伝える |
