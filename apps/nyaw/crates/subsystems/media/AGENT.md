# crates/subsystems/media

層: 1 Subsystems

OS 上で再生中のメディア（音楽・動画）に関するメタデータの取得および再生制御を担当する。

Windows 環境では Global System Media Transport Controls (GSMTC) セッションマネージャーを、Linux 環境では MPRIS（D-Bus）を使用する。OS ごとの問い合わせは `Backend` トレイトの実装（`src/windows.rs`、`src/linux.rs`）に閉じる。

## 非同期監視と画像処理

- **バックグラウンド監視**: ワーカータスクが 1 秒間隔でメディアセッションをポーリングし、タイトル、アーティスト名、再生状態、再生位置、曲長を取得する。
- **アートワークの前処理**: アルバムジャケット画像の縮小、UI 背景用のガウスぼかし処理、およびテーマ明暗判定用の平均輝度計算（`light`）をバックグラウンドスレッドで先行処理する。メインスレッドは計算済みの結果構造体を非同期に受け取る。
- **再生制御 (`Command`)**: 再生、一時停止、曲送り、曲戻し、シーク位置変更のコマンドを非同期に OS へ発行する。

## Linux（MPRIS）

セッションバスの `org.mpris.MediaPlayer2.*` を 1 秒間隔で列挙し、`Properties.GetAll` で状態を読む。D-Bus のクライアントは `zbus`（`desktop` が使う `ashpd` と共通）の同期 API を使う。

- **一覧に含めるプレイヤー**: 再生中と一時停止中のものだけを、バス名の順に並べる。他のプレイヤーを中継する `playerctld` は、中継元と重複するため除外する。
- **表示するプレイヤーの選び方**: MPRIS には、OS が現在のプレイヤーを定める仕組みが無い。切り替えで選んだものがなければ、再生中のものを優先する。すべて一時停止している場合と、複数が再生中の場合は、直前に表示していたものを保つ。
- **アプリの ID と表示名**: ID は `DesktopEntry`、`Identity`、バス名の順に、最初に得られるものを使う。表示名はプレイヤーが申告する `Identity` を優先する。アイコンは `desktop::installed_app` を `DesktopEntry`、`Identity` の順に引いて得る。Chromium 系は `DesktopEntry` を持たない場合があり、`spotify-launcher` で導入した Spotify は `DesktopEntry` と `.desktop` のファイル名が異なる。
- **値の型**: 仕様と異なる型を返すプレイヤーがあるため、整数の型は区別せず、曲の ID は文字列も受け付ける。Spotify は `mpris:trackid` を文字列、`mpris:length` を符号なし整数で返す。
- **操作の可否**: 再生・一時停止、曲送り、曲戻し、シークは `CanControl` と各操作の `Can*` の両方が真の場合だけ有効にする。シークは `SetPosition` で行うため、曲の ID（オブジェクトパスとして正しいもの）と曲の長さも必要とする。前面化は `CanRaise` に従う。ウィンドウが実際に前面へ出るかは、コンポジタとプレイヤーによる。
- **ジャケット**: `mpris:artUrl` はプレイヤーが申告する値であるため、`file`（通常のファイルに限る）と `https`（リダイレクト先を含む）だけを読み、大きさを 10 MiB までにする。`https` の取得は数秒かかる場合があるため別のスレッドで行う。取得中はジャケット無しで曲の情報を表示し、完了後の問い合わせで画像を読み込む。取得を待つ上限は 5 秒で、失敗した URL は取得し直さない。
- **応答しないプレイヤー**: D-Bus の呼び出しは 2 秒で打ち切り、そのプレイヤーを一覧から除く。応答しないプレイヤーがある間は、問い合わせの周期がその分だけ長くなる。
- **制約**: 同じ再生を複数のプレイヤーとして公開するもの（ブラウザと、ブラウザの連携機能など）がある場合は、別のセッションとして並ぶ。

## テスト手法

- **Linux の自動テスト**（`src/linux/tests.rs`）: テスト専用の `dbus-daemon` を起動し、`zbus` で作った模擬プレイヤーを登録して、読み取り、型の違い、選び方、操作の送信、ワーカーまでの流れを検証する。利用者のセッションバスには接続しない。実行には `PATH` 上の `dbus-daemon` が必要である。CI のテストは Windows で実行するため、このテストは CI では実行されない。
- **実機の確認**: `cargo run -p media --example now_playing [秒] [操作…]` は、取得した内容を 1 秒ごとに出力し、指定した操作（`switch`、`playpause`、`next`、`previous`、`seek=<秒>`、`raise`、`wait`）を 2 秒ごとに順に送る。操作は実際のプレイヤーに届くため、再生中の内容が変わる。

## 主な公開 API

```rust
Media::{
    start,          // バックグラウンド監視ワーカーの起動
    now,            // 現在の再生中メディア情報の取得
    send,           // 再生制御コマンドの送信
};
NowPlaying;         // 再生中メディアのメタデータ構造体
Command;            // 制御コマンド（Play, Pause, Next, Previous, Seek 等）
```
