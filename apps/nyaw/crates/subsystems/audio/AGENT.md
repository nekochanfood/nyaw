# crates/subsystems/audio

層: 1 Subsystems

OS への音声出力（cpal）、WAV オーディオファイルの読み込み、および Steam Audio による空間音響処理（HRTF バイノーラル立体化）を担当する。

音声のデコード、ミキシング、および立体音響計算は独立したオーディオ専用スレッドで実行され、メインスレッドはコマンド発行のみを行う。

## パネルスピーカーと 3 次元音響

各パネルには仮想的なスピーカー（音源）が配置され、3 次元空間内におけるパネルの姿勢と連動して再生される。

- **パネル全体の再生 (`PanelCommand::Play`)**: パネル全体を音源として音声を再生する。同一パネルまたは複数パネル間で複数の音声が重層して再生可能である。パネルを閉じると再生中の音声も連動して停止する。
- **特定点からの再生 (`PanelCommand::PlayAt`)**: パネル表面の特定ピクセル座標から一度だけ音声を鳴らす。仮想キーボードのキートップ打鍵音（打鍵位置ごとのピッチ微変動 1 ± 0.1 を適用）などで使用され、パネルごとに最大 8 個の音源が巡回再利用される。
- **スピーカーレイアウト (`Layout`)**:
  - `Layout::Auto`（既定値）: 入力音源が 1ch または左右同等の場合はモノラル（中心 1 点）、それ以外はステレオ（パネル両端 2 点）として扱う。
  - `Layout::Mono` / `Layout::Stereo`: スピーカー構成を明示的に固定する。
- **距離減衰特性**: リスナー（聞き手）は HMD の位置とする。距離 1m 以内は減衰せず、1m を超えると Steam Audio の逆距離減衰モデルに従って自然に音量が減少する。

## Steam Audio (HRTF) 連携とフォールバック

立体化処理には Steam Audio SDK のバイノーラル HRTF を使用する。

- **動的リンクとフォールバック**: 実行時に動的ライブラリ（Windows 環境では `phonon.dll`）を検索・ロードする。ライブラリが見つからない場合は、自動的に左右の等パワーパンニング（`Spatializer::Panning`）へフォールバックして動作を継続する。
- **SDK の自動取得**: `build.rs` がビルド時に指定バージョンの SDK を自動ダウンロードし、`phonon.dll` を出力ディレクトリへ自動配置する。環境変数 `NYAW_SKIP_PHONON` を指定することで、CI 環境などでのダウンロードをスキップできる。
- **ミキシング性能の最適化**: 256 サンプル単位でミキシングを行う。オーディオコールバック内でのメモリ確保を防ぐため、事前に 64 系統（32 音声 × 左右）の HRTF 状態を事前確保している。

## 主な公開 API

```rust
Engine::{
    open,            // 実オーディオデバイスを開いて初期化
    offline,         // テスト用のオフラインレンダラー
    render,          // オフラインバッファのレンダリング進行
    set_listener,    // HMD 姿勢（リスナー）の更新
    set_speaker,     // パネルスピーカーの姿勢更新
    play,            // 音声再生コマンドの発行
    stop,            // 再生停止
};
Speaker;             // パネルスピーカーの定義
Layout;              // スピーカー配置（Auto, Mono, Stereo）
Sound;               // 音声リソース指定（ファイルパスまたはインライン WAV）
Spatializer;         // 空間音響バックエンド（Hrtf または Panning）
```

## テスト手法

- **オフライン波形検証 (`cargo test -p audio -p kernel --lib`)**: `Engine::offline` を使用してデバイスを開かずにミキシングを実行し、左右チャンネルの出力波形と音量バランスを検証する。
- **実機再生テスト (`cargo test -p audio -- --ignored`)**: 実際に音声を出力して Steam Audio の HRTF 処理を検査する（環境変数 `NYAW_PHONON` で DLL を指定可能）。
